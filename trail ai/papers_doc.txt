1. Proposal verification
 The proposal is titled “TRIAL AI – AI-POWERED SMART TOURIST GUIDE”. It defines the objective as reducing
travel-planning friction by coordinating destination recommendation, route planning, budget estimation, hotel
recommendation, food/spot discovery and offline-oriented support.
 The proposal lists 16 research works. It does not formally label one paper as the sole 'exact base paper'. However, its
literature-survey table explicitly describes the 2025 “Smart Trip Planner for Personalized Tourism Itineraries” as very
close to Trial AI, while identifying integrated modules, offline readiness and orchestration as differentiation areas.
 The proposed technical architecture in the proposal is mobile application + Python/ML + Google Maps API +
Firebase.

4. Full prototype build prompt
You are a senior full-stack AI engineer and research-prototype architect. Build a working MVP named TRIAL AI –
AI-POWERED SMART TOURIST GUIDE. Treat the uploaded Trial AI proposal as the functional specification and the
five verified IEEE papers as research foundations. Do not copy copyrighted paper text, figures or source code.
Re-implement only the functional ideas needed for the prototype and clearly label research-inspired components.
GOAL:
Create one coherent tourist-assistance workflow that accepts a destination, dates, party size, budget and travel
preferences and returns a personalized, feasible, explainable trip plan containing attractions, route order, hotel options,
food options, estimated cost, map view and an offline-ready package.
TECH STACK:
- Frontend: React + Vite + TypeScript, responsive/mobile-first UI.
- Backend: Python FastAPI.
- Database/Auth: Firebase Authentication + Firestore.
- Maps/Places: Google Maps Platform (Geocoding, Places, Routes/Distance Matrix as applicable).
- Recommendation service: Python module with normalized feature scoring.
- Local/offline storage: browser IndexedDB for web MVP; if implementing native mobile, use the platform's local
database/cache.
- Optional AI layer: an LLM for natural-language preference parsing and itinerary explanation. Keep deterministic
scoring/constraints as the source of truth for feasibility.
INPUTS:
destination, start_date, end_date, number_of_travelers, age-group/category preferences when voluntarily provided,
budget, currency, interests, disliked categories, travel pace, food preferences, hotel preference, transport preference,
maximum daily travel time, accessibility requirements if provided, and optional free-text request.
DATA MODEL:
User, Trip, PreferenceProfile, POI, Hotel, FoodPlace, RouteSegment, DailyPlan, BudgetItem, OfflinePackage,
Feedback, RecommendationLog.
RECOMMENDATION ENGINE:
1. Parse user requirements into structured constraints.
2. Retrieve candidate POIs/hotels/food places.
3. Hard-filter impossible candidates: outside destination, closed at planned time, over strict budget cap, incompatible
constraints.
4. Compute explainable score:
score = w_pref*preference_match + w_context*context_match + w_distance*distance_score + w_rating*quality_score
+ w_budget*budget_fit + w_time*schedule_fit.
5. Normalize features to [0,1].
6. Show the top candidates and explain the main reasons for each recommendation.
7. Never fabricate live facts; if an API field is unavailable, mark it unknown or use clearly labeled mock data.
ITINERARY ENGINE:
- Convert ranked POIs into daily schedules.

- Respect opening hours, estimated visit duration, travel time, meal windows and daily time limits.
- Prevent impossible overlaps.
- Use a deterministic route/constraint algorithm first.
- Optional advanced mode: use a metaheuristic or multi-objective optimizer inspired by the research literature.
- Output day-by-day route order, time blocks, travel segments and reasons.
BUDGET ENGINE:
- Estimate hotel + transport + food + attraction/activity costs.
- Show itemized costs and total.
- Show min/expected/max where uncertainty exists.
- Clearly mark estimates versus live prices.
- Provide budget warnings when projected cost exceeds the user's limit.
- Do not claim price accuracy without current data.
HOTEL + FOOD:
- Query Places/API or seeded dataset.
- Filter by destination, rating/quality, price band, distance and preferences.
- Integrate selected hotel and food stops into the itinerary instead of presenting disconnected lists.
OFFLINE MODE:
- Add “Download Trip Offline”.
- Store itinerary, POI names, coordinates, essential descriptions, route sequence, emergency/contact information and
timestamps locally.
- When offline, display cached data and last-known route information.
- Clearly show that live traffic, live opening status and real-time prices require connectivity.
